# 鸿蒙验收标准写法（DwGuard Rubric）

验收标准写不好，后面所有审计都是表演。这份规则库把"功能/审美/性能/无障碍"翻译成可证伪的判据。

## 0. 三条铁律

1. **可观察**：写完这条判据，一个没参与开发的人能照着做一遍并得出"通过/不通过"。
2. **可反驳**：存在一种明确的失败情形。写不出失败情形，说明它不是判据，是口号。
3. **有证据**：判据自带取证方式（命令 / 截图 / 布局树 / 数值），而不是"由执行者确认"。

`dwguard_spec` 会拒绝：纯形容词、没有验证方式、验证方式依赖执行者自述、缺维度、ID 重复的判据。

## 1. 功能（DW-FN）

**公式**：给定 <前置条件>，当 <操作>，则 <可观察结果>。

| 规则 ID | 检查点 | 判据示例 |
| --- | --- | --- |
| DW-FN-01 | 主路径可完成 | 在首页点击「开始训练」，1s 内进入训练页，标题显示「今日训练」 |
| DW-FN-02 | 空态 | 列表无数据时显示空态插画 + 「去创建」按钮，点击进入创建页 |
| DW-FN-03 | 错误态与重试 | 断网时提交显示「网络异常，请重试」，点击重试后请求重发（日志可见第二次请求） |
| DW-FN-04 | 返回栈 | 从详情页连续返回两次回到首页，且首页列表滚动位置与进入前一致 |
| DW-FN-05 | 幂等 / 防重复 | 快速连点「提交」5 次，后台只产生 1 条记录 |
| DW-FN-06 | 状态恢复 | 切后台 30s 再回前台，页面数据不丢失、不重复加载 |
| DW-FN-07 | 权限拒绝 | 拒绝定位权限后，页面显示「开启定位」引导，不崩溃、不空白 |
| DW-STATE-02 | V2 深度观测 | `@ObservedV2` 类中 UI 用到的字段都有 `@Trace`；未 `@Trace` 的字段不参与刷新 |
| DW-STATE-03 | V1/V2 不混用 | V1 装饰器不修饰 `@ObservedV2` 类；V1 组件不接收 `@ObservedV2` 实例（应编译报错） |
| DW-STATE-04 | @Local 边界 | `@Local` 只在 `@ComponentV2` 中使用，且不从父组件传入初始化 |
| DW-STATE-05 | V2 父子通信 | 输入用 `@Param`、回调用 `@Event`；不用 `@Link` 做 V2 双向同步 |
| DW-STATE-06 | @Monitor 范围 | 只监听 `@Local/@Param/@Provider/@Consumer/@Computed`；类对象需整体监听，嵌套属性需 `@Trace` |
| DW-STATE-07 | @Computed 纯度 | 只装饰 getter、只读、不修改依赖、不做副作用、不与双向绑定连用 |
| DW-STATE-08 | @Provider/@Consumer | 只在 `@ComponentV2` 属性上、必须本地初始化、不能装饰 class、不接受外部传入 |
| DW-STATE-09 | V1→V2 迁移 | 按组件分批；@Watch→@Monitor、@Provide/@Consume→@Provider/@Consumer、@Link→@Param+@Event、@Observed→@ObservedV2+@Trace |

必查状态清单：首次进入 / 有数据 / 空数据 / 加载中 / 请求失败 / 无权限 / 深色模式 / 字体放大 / 横屏或折叠屏（如支持）。

**好**：`F-02 断网状态下点击「同步」，3s 内出现「网络异常，请重试」文案与重试按钮；点击重试后 hilog 出现第二条请求日志`
**坏**：`F-02 同步功能正常`

## 2. 审美（DW-AES）

审美判据不是"好看"，是**可度量的视觉一致性**。每条判据要能指出：哪个页面、哪个元素、什么值、对照哪条规则。

| 规则 ID | 检查点 | 判据示例 |
| --- | --- | --- |
| DW-AES-01 | 8vp 栅格 | 首页卡片左右边距 16vp、卡片间距 12vp，与 8vp 栅格对齐（允许 4vp 半格） |
| DW-AES-02 | 字号层级 | 全页字号不超过 4 级：标题 24fp / 小标题 18fp / 正文 16fp / 说明 14fp |
| DW-AES-03 | 圆角与阴影一致 | 同类卡片圆角统一 16vp；阴影只用于浮层，普通卡片用 1vp 描边 |
| DW-AES-04 | 颜色语义 | 主色只用于主操作；成功/警告/错误三色与设计 token 一致，错误色不用于装饰 |
| DW-AES-05 | 留白与对齐 | 同组元素左对齐；标题与正文间距 ≥ 8vp；区块之间 ≥ 24vp |
| DW-AES-06 | 图文比例 | 缩略图统一 4:3，裁切不变形；文字不压图（对比度另见 A11Y） |
| DW-AES-12 | 按钮响应式 | 单按钮最大 448vp；多按钮等宽、间距 12vp；容器两侧 16vp（布局树 bounds 实测） |
| DW-AES-13 | 列表行高 | 效率型 48/56/64/72/96vp；内容型 64/72/80/96/120vp；右侧元素间距 12vp |
| DW-AES-14 | 文本框 | 有标签/占位符；错误提示在框下；密码掩码；计数器“已输入/上限” |
| DW-AES-15 | 弹出框 | 宽 ≤400vp；高 ≤0.9×(屏高-状态栏-导航栏)；≥3 按钮改上下布局 |
| DW-AES-16 | 标题栏 | 普通单行 56vp、强调型 112vp；右侧图标（含更多）≤3；一级页不出现返回 |
| DW-AES-17 | 底部页签 | 3–5 个；平铺 48vp / 悬浮 56vp；图标 24vp；避让系统导航条 |
| DW-AES-18 | 开关 | 开/关状态可区分；仅点开关切换；重要功能二次确认 |
| DW-AES-19 | 进度条 | 确定进度显示百分比并实时更新；未知用无限循环；<400ms 按 400ms 线性动画 |
| DW-AES-20 | Symbol 图标 | 标准 24×24vp（主体 22×22）；描边 1.5vp；混排用 SymbolSpan |
| DW-AES-21 | 卡片式列表 | 同组圆角/间距/对齐一致；不混排不同结构；卡片间 ≥12vp |

写法模板：`A-01 <页面/元素> 的 <属性> 为 <值>，与 <规则 ID> 一致`，取证方式写「截图 + 布局树 bounds 实测」。

**好**：`A-02 首页卡片间距 12vp、圆角 16vp，与详情页卡片一致（DW-AES-03）`
**坏**：`A-02 界面美观、符合鸿蒙设计规范`

## 3. 性能（DW-PERF）

性能判据必须带数值和测量方式；阈值由项目定，下面是可用的默认值（写进 `constraints` 后可覆盖）。

| 规则 ID | 检查点 | 默认阈值 | 测量方式 |
| --- | --- | --- | --- |
| DW-PERF-01 | 冷启动到首帧 | ≤ 800ms（中端机） | DevEco Profiler 启动分析 / hilog 时间戳 |
| DW-PERF-02 | 长列表滚动 | 100 项列表滚动无明显丢帧（≤ 2 帧/秒卡顿） | Profiler 帧率图 + 录屏 |
| DW-PERF-03 | 内存与泄漏 | 反复进出页面 10 次，内存不持续增长（±5MB 内） | Profiler 内存曲线 |
| DW-PERF-04 | 包体 | HAP 体积增量 ≤ 2MB / 单张图片 ≤ 300KB | 构建产物 `build/default/outputs/` |
| DW-PERF-05 | 重活不占主线程 | 解析/排序/大图解码不在 `build()` 或 `aboutToAppear` 同步执行 | 代码审查 + Profiler 火焰图 |
| DW-PERF-10 | 冷启动五阶段 | 进程创建 → Ability 生命周期 → 首帧分段耗时可见；首帧 ≤ 800ms（中端机） | SmartPerf/Profiler Trace + 分段截图 |
| DW-PERF-11 | 无超长帧 | 滑动 5s 无 > 33.3ms 超长帧；记录设备型号与刷新率 | Trace/Frame + 丢帧率 |

**好**：`P-01 冷启动到首帧 ≤ 800ms，3 次取中位数，Profiler 截图佐证`
**坏**：`P-01 性能流畅不卡顿`

## 4. 无障碍（DW-A11Y）

| 规则 ID | 检查点 | 阈值 / 做法 |
| --- | --- | --- |
| DW-A11Y-01 | 文字对比度 | 正文 ≥ 4.5:1，大字号（≥18pt 或 14pt 粗体）≥ 3:1（WCAG 2.2 AA） |
| DW-A11Y-02 | 触控目标 | 可点击元素 ≥ 48vp × 48vp，相邻目标间距 ≥ 8vp |
| DW-A11Y-03 | 焦点可见与顺序 | 键盘/遥控遍历时焦点框可见，顺序符合阅读顺序，不跳焦点、不丢焦点 |
| DW-A11Y-04 | 可访问名称 | 纯图标按钮必须有 `accessibilityText`；图片有语义时补描述，装饰图设 `accessibilityLevel('no')` |
| DW-A11Y-05 | 字体放大 | 系统字体放大到 1.3x / 1.75x，文字不截断、不重叠、不超出容器 |
| DW-A11Y-06 | 非颜色编码 | 状态不能只靠颜色区分（错误同时有图标或文案） |
| DW-A11Y-07 | 动效可关闭 | 系统开启「减少动态效果」时，非必要动效降级为淡入或直切 |
| DW-A11Y-09 | 分组播报 | 卡片/整行用 `accessibilityGroup(true)` 合并播报，内部文字不被逐个聚焦 |
| DW-A11Y-10 | 无障碍层级 | 纯装饰元素 `accessibilityLevel('no')`；不可用整块用 `no-hide-descendants` |
| DW-A11Y-11 | 提示分离 | `accessibilityText` 只讲“是什么”，操作方式放 `accessibilityDescription` |
| DW-A11Y-12 | 键盘可达 | 外接键盘 Tab / 遥控器能遍历全部交互元素，焦点激活态可见 |
| DW-A11Y-13 | 2x 字体 | 系统字体 2x：文字不截断、不重叠、不出容器；弹窗内容按 2x 封顶不溢出 |

对比度速算：相对亮度 `L = 0.2126R + 0.7152G + 0.0722B`（R/G/B 先做 sRGB 线性化），对比度 `(L1+0.05)/(L2+0.05)`。正文 #1A1A1A 配 #FFFFFF ≈ 17.4:1。

**好**：`X-01 主按钮文字 #FFFFFF on #0A59F7 对比度 4.8:1（≥4.5:1）；按钮 48vp×48vp`
**坏**：`X-01 支持无障碍`

## 5. 一页模板（复制使用）

```text
需求：<用户原话 + 目标>
规格：<页面/组件结构、状态流向、数据来源、关键交互>

功能
- F-01 给定…当…则…（规则 DW-FN-01；验证：操作步骤 + 截图/日志）
- F-02 嵌套属性整体替换（规则 DW-FN-12 / STATE-NESTED-01；验证：dwguard_scan 无命中）
审美
- A-01 <页面/元素> 的 <间距/字号/圆角/颜色> = <值>（规则 DW-AES-0x；验证：截图 + 布局树实测）
性能
- P-01 <指标> ≤ <阈值>（规则 DW-PERF-0x；验证：Profiler / hilog 时间戳）
无障碍
- X-01 <元素> 对比度 ≥ 4.5:1（规则 DW-A11Y-01；验证：取样计算 + 截图）
- X-02 可点击元素 ≥ 48vp，焦点顺序 A→B→C（规则 DW-A11Y-02；验证：布局树 bounds + 焦点截图）

约束：compatibleSdkVersion 5.0.0(12)；不改 AppScope；包体增量 ≤ 2MB
```

每条判据在 `dwguard_spec` 里用 `ruleId` 指向规则目录（`DW-*`，或别名 `STATE-NESTED-01` / `AGC-RJ-013`）。
`dwguard_scan` 命中、`dwguard_audit` 的 findings 也用同一套 ID——报告里就能写
「违反 `DW-FN-12`（= `STATE-NESTED-01`）」而不是「代码写得不太对」。

## 6. 常被拒绝的写法（对照检查）

| 会被拒绝 | 原因 | 改成 |
| --- | --- | --- |
| 界面美观 | 纯形容词 | 具体间距/字号/圆角 + 规则 ID |
| 性能流畅 | 无数值 | 首帧 ≤ 800ms / 丢帧 ≤ 2 帧每秒 |
| 自测通过 | 依赖执行者自述 | 独立命令 + 证据 |
| 功能正常 | 不可证伪 | 给定-当-则 |
| 支持无障碍 | 无边界的"支持" | 对比度/触控/焦点/命名逐条 |

## 7. 可执行断言（assertion，0.5.0 起）

判据只要能量出数值，就应补一个 `assertion`，让 `dwguard_audit` 自己重算结论（人只负责取 `actual` + 附证据）：

```jsonc
{
  "id": "P-01",
  "dimension": "performance",
  "statement": "冷启动到首帧 ≤ 800ms",
  "verify": "Profiler 启动分析毫秒数",
  "ruleId": "DW-PERF-01",
  "assertion": { "matcher": "lte", "expected": 800, "unit": "ms" }
}
```

| matcher | 写法 | 例子（actual → 结论） |
| --- | --- | --- |
| `equals` | 字符串或数字 | `"4"` → 4 天；数值优先数值比较 |
| `contains` | 子串（大小写不敏感） | `"连续天数 4"` 含 `"连续"` |
| `regex` | 正则（自行加 `^$`） | `"4.9:1"` 匹配 `^\d+\.\d+:1$` |
| `range` | `min` 和/或 `max` | `"12vp"` ∈ [8,16] |
| `gte` / `lte` | 数值阈值 | `"720ms"` ≤ 800 |
| `oneOf` | 非空数组（可传 JSON 数组字符串） | `"深色"` ∈ ["浅色","深色"] |
| `present` | 非空即可 | 截图路径 / 文案 |

注意：

- 数值类 matcher 取 `actual` 里的**第一个数字**，所以实测值可以带单位（`12vp`、`720ms`、`4.9:1`）；
- 带 `assertion` 的判据，审计时 `checks[].actual` **必填**；断言不通过却写 `pass` 会被闸门拒绝；
- 写不出断言的判据（如"看起来舒服"）说明还没可证伪，请改写判据而不是硬造断言。

## 8. 引用审美档案（`profileRef`，0.6.1 起）

用户确认过的审美数值不用每轮重新争论：先把它写进审美档案，判据只引用档案 ID。

```jsonc
{
  "id": "A-02",
  "dimension": "aesthetic",
  "statement": "卡片圆角与审美档案 AES-RADIUS-01 一致（20vp）",
  "verify": "布局树 bounds 实测圆角 + 截图对照",
  "ruleId": "DW-AES-04",
  "profileRef": "AES-RADIUS-01",
  "assertion": { "matcher": "range", "min": 18, "max": 22, "unit": "vp" }
}
```

- 档案用 `dwguard_aesthetic`（`profile write` 需 `source` + `confidence`；或 `learn` 提议后用户确认再 `apply`）维护；
- 审计闸门会拒绝**不存在**或**已 superseded** 的 `profileRef`，并在审计/验收报告里渲染「审美档案」与「审美基线差异」；
- 基线回归用 `compare`：间距/圆角 ±2vp、字号与颜色 0 容差；差异是回归还是新设计，由用户拍板并重建基线。
