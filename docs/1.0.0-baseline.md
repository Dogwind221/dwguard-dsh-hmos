# DwGuard-Dsh-Hmos 1.0.0 — first public baseline

Date: 2026-11-16

This is the first baseline intended for other developers. It is **not** a
production service and does not claim multi-tenant scale, SLOs or physical-device
coverage.

## What is included

- DSH-HarmonyOS task pack → adversarial pre-review → DevEco dispatch →
  four-dimension audit → rework → knowledge loop.
- Standalone CLI: `doctor`, `review`, `checker`, `bridge`, `bench`, `quickstart`.
- Typed evidence contract: `requiredEvidence`, `evidenceRefs`,
  `coverage.evidence`, pass → unverified when declared evidence is missing.
- Design knowledge: 167 Huawei UX documents as citation/summary index, 1,164
  section-level entries, link-only design resources, design foundations bound
  to `DW-AES-*` / `DW-A11Y-*`.
- DshHoms precision-console visual layer.

## Install

Requires DSH `>=0.2.1-rc.0 <0.3.0`; verified boot on DSH 0.2.2-rc.1.

```powershell
dsh plugin --profile <profile> add dwguard-dsh-hmos@1.0.0
```

Or install `dwguard-dsh-hmos` from the DSH plugin UI. Do not use plain
`npm install` as the plugin installation path.

## Known limits

See [known-limitations.md](known-limitations.md). In short:

- CLIP live endpoints are optional; image search falls back to pHash/histogram,
  text→image needs CLIP.
- Single-user/local `.shared`; no multi-tenant or high-concurrency load proof.
- No monitoring, alerts, backup, SLO, on-call or HA.
- No physical HarmonyOS device: physical benchmark is blocked.
- Marketplace catalog refresh is delayed and not guaranteed.
- Design guides are citation/summary only; no official bodies/images/assets.

## Not in 1.0.0

- Multi-tenant hosting
- Production SLO/backup/on-call
- Full physical-device matrix
- Guaranteed CLIP availability
- Go runtime checks (`go test`, `vet`, `-race`) — this is a TypeScript plugin
