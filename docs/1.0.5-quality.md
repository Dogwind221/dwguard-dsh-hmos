# 1.0.5 — 验收六件套（截图回归 / 性能 / 场景 / 无障碍 / 包审计 / 稳定性）

1.0.5 把验收从「单点取证」推进到**可回归、可量化、可重放**：截图基线、性能采样、
场景回放、运行时无障碍、包/权限审计、稳定性门禁。

工具数仍是 **17**；`dwguard_deveco` 动作数 26 → **29**（新增 `perf` / `scenario` / `stability`）。
新增能力全部是 additive；旧 action/参数不变。

## 1. 截图视觉基线 + diff（`dwguard_aesthetic compare`）

```jsonc
// 存基线时带上截图（与 bounds 一起）
{ "action": "baseline", "op": "save", "page": "home", "state": "default",
  "bounds": "artifacts/deveco-3/layout.json", "screenshot": "artifacts/deveco-3/home.png" }

// 下一轮比较：数值 + 截图一起比
{ "action": "compare", "page": "home", "state": "default",
  "bounds": "artifacts/deveco-9/layout.json", "screenshot": "artifacts/deveco-9/home.png",
  "pixelThreshold": 12, "passRatio": 0.005 }
```

- 数值部分仍是布局树指标（间距/圆角/字号/颜色，±2vp 容差）。
- 截图部分新增：pHash 距离、变化像素比例、平均亮度差、按 4×4 区域列出超容差区域、`diff-*.png` 差异图。
- 通过条件：数值全过 **且** 截图 `changedRatio ≤ passRatio` 且 `phashDistance ≤ 12`；尺寸不一致时明确报 `dimensionMismatch`，不伪造像素指标。
- 证据：`compare-latest.json` 增加 `imageDiff` / `imageDiffFile`；验收报告自动渲染「截图差异」小节。

## 2. 性能实测值（`perf`）

```jsonc
{ "action": "perf", "op": "startup", "bundle": "com.demo.app", "ability": "EntryAbility",
  "samples": 3, "warmup": 1, "device": "127.0.0.1:5555" }
{ "action": "perf", "op": "memory", "bundle": "com.demo.app" }
{ "action": "perf", "op": "frame" }
```

- `startup`：主机侧计时 `hdc shell aa start -b <bundle> -a <ability>`，去掉 warmup，输出 samples / mean / min / max / p95（ms）。
- `memory`：`pidof` → `hidumper --mem <pid>`，解析 Pss（KB）。
- `frame`：`hidumper -s RenderService -a fpsCount`，解析 fps / refresh rate；没有 fps 字段时单位为 Hz（只是刷新率计数，不冒充 app 帧率）。
- 证据：`perf.json`（samples + unit + 聚合值），可直接填进审计 `actual` 的 `samples` + `aggregation: p95`。
- 边界：startup 含 hdc 开销；frame 依赖设备 RenderService 输出；解析不到数字时明确失败，不编造数值。

## 3. 场景回放（`scenario`）

```jsonc
{ "action": "scenario", "device": "127.0.0.1:5555",
  "scenario": [
    { "op": "click", "x": 360, "y": 1200 },
    { "op": "text", "text": "hello", "id": "input" },
    { "op": "swipe", "x1": 700, "y1": 1500, "x2": 100, "y2": 1500 },
    { "op": "assert", "selector": "text=成功", "expect": "present" },
    { "op": "screenshot", "name": "after-submit" }
  ],
  "stability": true }
```

- 步骤：`click`（坐标或 `id`）/ `text` / `swipe` / `sleep` / `screenshot` / `assert`（present/absent/count）。
- 每步写 `step-<i>.json`（命令/退出码/证据路径），汇总 `scenario-run.json`；失败的步骤立即停（`continueOnFailure` 可改为继续）。
- 设备锁覆盖整个场景；`screenshot` 步骤直接落到 `artifacts/deveco-<n>/`。
- 步骤数 1–40；JSON 可内联或放在工作区文件里（`scenario` 传路径）。
- 通过时生成 observation，可作为 audit 证据。

## 4. 运行时无障碍（`a11y op=runtime`）

```jsonc
{ "action": "a11y", "op": "runtime", "device": "127.0.0.1:5555",
  "minTouch": 44, "minContrast": 4.5 }
```

- 同时抓 `ui layout --format json --mode full` + `ui screenshot`。
- `bounds` 计算可点击节点的最小触控尺寸（默认 44）；`text` 节点区域从截图采样亮度范围，估算对比度，低于阈值（默认 4.5）列为风险。
- 证据：`a11y-runtime.json`（节点/可点击/文本节点计数、触控过小列表、对比度风险列表）。
- 边界：对比度为**区域亮度范围估算**，不是字体颜色/背景色的精确采样；是否阻断由任务包判据决定。

## 5. 权限 / 包体 / 签名 / 隐私审计（`project op=audit`）

```jsonc
{ "action": "project", "op": "audit", "maxHapMb": 20 }
```

- 声明权限：各模块 `module.json5` 的 `requestPermissions`（name/reason/usedScene）。
- 引用权限：扫描工程内 `ohos.permission.*` 字符串。
- 差异：源码引用但未声明（blocker）、声明但源码未引用（minor）。
- 隐私：缺 `reason` 或 `usedScene` 的声明（major）。
- 产物：HAP/HSP 大小、SHA-256、`META-INF` 签名文件存在性（结构性检查，**非密码学验签**）。
- 体积预算：`maxHapMb` 超出记 major。
- 证据：`project-audit.json`；存在 blocker 时整体失败。

## 6. 稳定性门禁（`stability` / `scenario.stability`）

```jsonc
{ "action": "stability", "device": "127.0.0.1:5555", "tail": 300 }
{ "action": "scenario", "scenario": [...], "stability": true }
```

- 收集 `log --crash` 与 `log --tail N`，解析 crash/freeze + hilog 错误折叠。
- 产出 `stability.json`：crashes / freezes / errorCount / passed / crashTail / hilogTail。
- 有条目 crash 或 appfreeze 即整体失败；hilog 错误数只统计，是否阻断由判据决定。

## 8. 边界

- 截图 diff 只覆盖「画面是否变化」；颜色/间距的精确值仍看数值基线与布局树。
- perf 的 startup 含 hdc 开销，frame 依赖 RenderService；不要拿单个样本当稳定值。
- scenario 是**回放**，不是录制器：坐标/选择器需自己写，UI 改版要维护步骤。
- 包审计的签名检查是结构性的；需要验签时请用 DevEco 工具链单独做。
- 稳定性门禁只覆盖收集窗口；长时间运行的泄漏/偶现问题仍需重复场景。
