# 0.8.7 L4 证据：CI 矩阵与 100 轮 soak

> 这是 L4 证据的一部分，不是 L4 认证。真实项目、物理设备、独立审计和外部采用仍需单独完成。

## CI 矩阵

`.github/workflows/ci.yml` 在 Ubuntu / Windows / macOS × Node 24 上执行：

```text
npm ci
→ npm run typecheck
→ npm run build
→ git diff --exit-code
→ npm test
→ node scripts/verify-publish.mjs
```

`git diff --exit-code` 防止 `src` 已改、提交的 `lib/` 未重建；`verify-publish` 防止 pack 漏掉运行时资产。

## 100 轮 soak

命令：

```text
npm run soak:100
```

`scripts/soak.mjs` 顺序跑完整测试套件 100 次；每轮使用独立 `DSH_HOME`，记录：

- 轮次、状态、退出码、耗时；
- 测试通过/失败数；
- 失败轮完整输出 `artifacts/soak/round-<n>.log`；
- 汇总 `artifacts/soak/summary.json`。

### 第一轮发现并修复的真实 flake

第一次 100 轮在第 6 轮出现：

```text
EPERM: operation not permitted, open ...\.shared\state.json.lock
```

根因：Windows 上 `open(lock, 'wx')` 在锁文件竞争/索引器/杀毒扫描时可能返回
`EPERM`/`EACCES`，而 `withFileLock` 只把 `EEXIST` 视为竞争。

修复：`EPERM`/`EACCES` 也按竞争处理，重试到超时；同时关闭可能已打开的 handle。
这轮失败是 L4 证据本身的价值——它抓到了一个只在重复运行时出现的平台问题。
