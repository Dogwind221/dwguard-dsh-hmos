# AGC 上架与隐私合规检查清单

> 依据华为官方《应用审核指南》（50104）、《应用审核 Checklist》（50170）与《APP 常见个人信息保护问题 FAQ》（faq-05）。规则 ID 见 `dwguard_rules`（`DW-AGC-01~09`）。

## 1. 开发前

- [ ] **APP 备案**：鸿蒙包名也要备案；主体信息、名称、包名与在架信息一致（`DW-AGC-05` 相关）。
- [ ] **应用名称**：≤15 汉字 / 30 字符；不得是泛词、热门词、堆砌关键词；与软著/版号一致（`DW-AGC-09`）。
- [ ] **图标/截图**：图标不得用系统图标、不得带误导角标；截图 ≥3 张、方向正确、无重复/模糊/拉伸（`DW-AGC-05`）。
- [ ] **特殊行业资质**：生成式 AI、金融、医疗等按 `80301` 准备资质。

## 2. 开发中

- [ ] **隐私政策**：首次启动弹窗或登录页显著提示；**同意前不收集**任何个人信息（`DW-AGC-02`）。
- [ ] **权限最小化**：`module.json5` 只声明实际用到的权限；敏感权限弹窗同步写用途（`DW-AGC-04`）。
- [ ] **拒绝权限**：不退出、不循环弹窗、仍可登录/使用基本功能（`DW-AGC-03`）。
- [ ] **隐私双清单**：二级菜单展示“已收集个人信息清单”“第三方共享清单”，含种类/目的/场景/共享方式（`DW-AGC-07`）。
- [ ] **不绕过审核更新**：不动态下发可执行代码、不做热更新替换（`DW-AGC-08`）。
- [ ] **调试开关**：发布构建关闭调试，`debuggable=false`（`DW-AGC-01`）。

## 3. 签名与构建

1. 在 AGC 申请**发布证书**与**发布 Profile**（不是调试证书）；
2. 把 `signingConfigs` 写进 `build-profile.json5`，发布构建显式指定；
3. 构建：

```powershell
devecocli build --build-mode release --signing-config <name>
# 或 hvigorw assembleHap --mode module -p product=default -p buildMode=release
```

4. 校验：安装包签名链正确、`debuggable=false`、版本号与 AGC 提审信息一致（`DW-AGC-01`）。

## 4. 提审材料

- [ ] 应用名称/图标/介绍/截图与实际安装一致；无 test/demo/beta（`DW-AGC-05`、`DW-AGC-09`）。
- [ ] 需登录的应用提供**可用测试账号**，可完成登录-浏览-操作-退出（`DW-AGC-06`）。
- [ ] 需设备/特殊环境的提供演示视频（`DW-AGC-06`）。
- [ ] 隐私标签、分类标签、年龄分级如实填写。
- [ ] 提审前跑一遍“上架自检”/云测试，覆盖功耗、性能、兼容性、稳定性、UX、隐私。

## 5. 取证（对应审计 checks）

| 规则 | 证据 |
| --- | --- |
| AGC-01 | 构建配置截图 + `bm dump`/签名校验输出 |
| AGC-02 | 首次冷启动截图 + 同意前网络/日志 |
| AGC-03 | 逐权限拒绝录屏/截图 |
| AGC-04 | 权限弹窗截图 + `module.json5` 权限清单 |
| AGC-05 | AGC 资料页 vs 设备桌面/应用内截图对比 |
| AGC-06 | 测试账号登录-操作-退出录屏 |
| AGC-07 | 二级菜单双清单截图 |
| AGC-08 | 代码审查 + 更新链路说明 |
| AGC-09 | 文案/截图审查记录 |

> 拿不到官方原文的条目只做 `warn`/文档，不写成 `must`；本清单每条都能在 `50104` / `50170` / `faq-05` 找到对应段落。
