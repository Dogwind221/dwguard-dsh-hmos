# 1.0.4 — 工作台补全与性能切片

1.0.4 把 1.0.3 的取证闭环再补三块：**trace 切片统计**、**device=all 扩展到 trace/app**、以及 P1 的 **db / 模拟器状态注入 / hilog follow**。

工具数仍是 **17**；`dwguard_deveco` 动作数 25 → **26**（新增 `db`）。

## 1. `trace`：原始 trace + 切片统计

```jsonc
{ "action": "trace", "duration": 2, "device": "127.0.0.1:5555" }
{ "action": "trace", "duration": 2, "device": "all", "categories": "ability graphic ace app" }
```

- 单台：`trace.txt`（原始）+ `trace-summary.json`（统计）。
- `device=all`：每台 `trace-<i>-<sn>.txt` + `trace-summary-<i>-<sn>.json`，汇总 `trace-matrix.json`。
- 统计字段：
  - `lines` / `bytes` / `entries` / `written`
  - `events` / `beginEvents` / `endEvents` / `functions`
  - `spanMs` / `firstTimestamp` / `lastTimestamp`
  - `topFunctions[]`：`name`（数字归一化，跨运行稳定）/ `count` / `totalMs` / `maxMs` / `avgMs`
  - `slowest[]`：配对到的最长单次切片（name/pid/ms）
  - `topPids[]`
- 配对算法：同一 pid 的 `B|pid|<name>` 与 `E|pid` 按栈 LIFO 配对，时长 = 结束时间戳 − 开始时间戳；名字里 `0x…`→`<hex>`、数字→`<n>` 后聚合。
- **不做 fps/jank 判定**：统计只描述本次窗口的切片分布；性能判据仍需独立测量值（帧率、启动耗时等）。
- hitrace 的退出码不可靠：分类写错时仍返回 0；插件按输出里的 `error:` 判失败并列出 `hitrace -l` 的可用分类。

实测（Mate X7，HarmonyOS 6.1.1，2s，默认分类）：185 行 / **170 事件** / 36 个函数 / 跨度 1965ms；Top 切片为 `Native async work execute callback`（13.57ms 总长，最长 9.89ms）。

## 2. `app device=all`：逐台只读查询

```jsonc
{ "action": "app", "op": "list", "device": "all" }
{ "action": "app", "op": "foreground", "device": "all" }
{ "action": "app", "op": "info", "device": "all", "bundle": "com.demo.app" }
```

- 只对 `list / foreground / info` 做 fan-out；`install / start / stop / clearcache / cleardata` 仍要求逐台指定设备（避免误操作整池）。
- 每台写 `app-<i>-<sn>.json`，汇总 `app-matrix.json`（`passed` + 每台结果）。
- 任一设备失败 → 整体失败；不要用单台结果代表矩阵。

## 3. `db`：设备 SQLite 只读查询（新增 action）

```jsonc
{ "action": "db", "db": "/data/app/el2/100/database/com.demo/rdb/store.db",
  "sql": "SELECT id, name FROM user LIMIT 20", "device": "127.0.0.1:5555" }
```

- 命令：`devecocli device sqlite3 <db-path> <sql> --device ...`。
- **只读**：SQL 必须以 `SELECT` / `WITH` / `EXPLAIN` 开头，且只能一条语句（不允许分号）；写语句直接拒绝。
- 证据：`db-query.json`（sql / device / 输出行数 / stdout 截断）。
- 边界：HarmonyOS 的 SELinux 可能禁止 shell 域 sqlite3 打开应用库（本机 Mate X7 模拟器即如此）；被拒时用 `file op=recv` 把库拉到工作区，在主机侧只读分析。

## 4. 模拟器状态注入（结构化参数）

```jsonc
{ "action": "emulator", "op": "fold", "emulator": "S1", "foldState": "half-open" }
{ "action": "emulator", "op": "battery", "emulator": "S1", "batteryLevel": 80, "batteryStatus": "charging" }
{ "action": "emulator", "op": "geolocation", "emulator": "S1", "latitude": 31.2, "longitude": 121.5 }
{ "action": "emulator", "op": "sensor", "emulator": "S1", "sensor": "steps=42,light-intensity=500" }
```

- 参数会映射成 devecocli 的 `--level / --status / --latitude / --longitude / --steps / --light-intensity / …`；范围与 key 白名单在插件侧校验。
- 用途：矩阵/屏幕族验收前，把折叠态、电量、GPS、传感器固定成可复现状态，再跑 `uiassert device=all` / `trace device=all`。

## 5. `log op=hilog`：follow + 过滤

```jsonc
{ "action": "log", "op": "hilog", "follow": true, "level": "E",
  "bundle": "com.demo.app", "keyword": "Failed", "regex": "timeout|exception",
  "pid": 4321, "args": "--tail 100 --from 30s", "device": "127.0.0.1:5555" }
```

- `follow: true` 自动转**后台任务**（流式日志不能等一次返回）：返回 `deveco-<n>` job id，用 `jobs` 查看、`stop` 终止；输出在 `artifacts/deveco-<n>/output.log`。
- 过滤分层：`level` / `bundle` / `keyword` / `args(--tail/--from/--to)` 传给 devecocli；`regex` / `pid` 是插件侧过滤（只在一次性 `op=hilog` 的摘要里生效）。
- 一次性模式仍写 `hilog-summary.json`；follow 模式只留流式日志，不生成摘要（用 `jobs` + `log --follow` 的原始输出分析）。

## 6. 验证

- `npm test`：**225/225**（1.0.4 新增 6 个用例）。
- Mate X7 模拟器实测：
  - `trace` 2s：185 行 / 170 事件 / 36 函数 / 1965ms 跨度，切片统计正确；
  - `emulator fold half-open`、`emulator battery --level 80 --status charging` 生效；
  - `log op=hilog follow` 后台启动成功（pid 记录、`output.log` 生成）；
  - `db` 因模拟器 SELinux 拒绝 shell 域访问 SQLite 文件，未做设备侧 live 验证（单测覆盖命令与只读校验；文档给出 `file recv` 兜底）。

## 7. 边界

- trace 统计不是性能判定；不要把 `topFunctions[0]` 直接当“性能问题”，它只是热点排序。
- `device=all` 依赖 `device.pool`；空池会明确失败。
- `db` 只保证“SQL 只读”，不保证“设备允许访问”；SELinux 拒绝是设备事实，不是插件错误。
- `follow` 后台任务会一直跑，验收结束记得 `stop`。
