# 0.9.0 方案：设备基准、自动回传、独立复核、doctor

状态：**已实现（0.9.0 基础版）** · 前置 0.8.8

## 实测（2026-11-09）

- `doctor` 对 `quickstart` 工程：project / devecocli / hdc / device 全 `ok`；
- `bench --faults`：5 个内置故障用例全部通过；
- `bench --device`（Pura 90 模拟器）：env / build / screenshot / layout 全 `ok`；
- 同一命令加 `--require-physical`：明确 `blocked`，退出码 **2**，没有伪造物理设备通过；
- `quickstart --dir ... --api 24`：生成工程并 build 成功；
- 当前环境没有物理鸿蒙手机，所以 0.9.0 只能交付“设备基准入口 + 明确 blocked”，不能交付物理设备通过证据。

## 1. 物理设备 + 故障注入基准

- `bin/dwguard.mjs bench --faults`：内置故障用例，验证复核、doctor、bridge 在缺失/篡改输入下的行为；结果写入 `.shared/bench/faults-*/`。
- `bin/dwguard.mjs bench --device`：检测设备，执行 `devecocli` 版本、build、screenshot、layout；截图校验文件头，布局校验 JSON。
- `--require-physical`：只有模拟器时明确 `blocked`，退出码 2，不伪造物理设备证据。
- 没有设备时不生成“通过”结论。

## 2. DevEco 自动回传桥

- `bin/dwguard.mjs bridge --workspace <root> --once` 或常驻轮询。
- 读取 `.shared/outbox-deveco.md`，解析 `deliver/ack/question/blocked` 等记录；
- 新记录追加到 `.shared/bridge/events.jsonl`；
- 同一 `#a-N` 去重后入队 `.shared/harness/queue.json` 的 `delivery-review` 任务，供 `scripts/harness-worker.mjs` 领取；
- 游标 `.shared/bridge/state.json`，重复执行不会重复入队。

## 3. 独立证据复核 CLI

- `bin/dwguard.mjs review --workspace <root> [--audit N]`。
- 不依赖 DSH 进程，重算 `audit-<n>/manifest.json` 中每个证据文件的 SHA-256/字节数；
- 校验 `storedAs` 不逃逸证据包、`path` 不逃逸 `.shared`、无重名；
- 校验 manifest/audit 的 specVersion、checks、auditId；
- 校验 gate 与 acceptance-report / rework 单一致，且当前 spec 未漂移；
- 退出码 0/1/2，可用于 CI。

## 4. doctor + 十分钟示例

- `doctor` 检查 Node、项目结构、`.shared`、磁盘、`devecocli`、`hdc`、设备、设备 lease；
- `quickstart --dir ... --api 24` 用 `devecocli create` 生成示例并 build，不手写目标 App 源码；
- 十分钟步骤见 [quickstart-10min.md](quickstart-10min.md)。

## 非目标

- 不在 0.9.0 内伪造物理设备结果；没有物理设备就 `blocked`。
- 不把 bridge 做成网络服务；它是本地文件桥，由调度器/worker 运行。
- 不在本版实现跨机器分布式队列。
