# 1.0.2 — DevEco 工作台动作（`dwguard_deveco` 扩展）

1.0.2 没有新增工具（仍是 **17 个工具**），而是把 `dwguard_deveco` 的动作面从
17 个扩到 **25 个**，补上「把手机、工程和 SDK 变成可编程对象」的部分：

| action | 做什么 | 证据粒度 |
| --- | --- | --- |
| `emulator` | 模拟器：`list` / `start` / `stop` / `create` / `delete` / `rotate` / `volume` / `fold` / `battery` / `geolocation` / `scene` / `sensor` / `power` / `shake`；`start` 可加 `background: true` 后台启动 | `deveco-<n>/result.json`（list 另存 `emulators.json`） |
| `app` | 应用生命周期：`list` / `foreground` / `info` / `start` / `install` / `uninstall` / `stop` / `clearcache` / `cleardata` | `deveco-<n>/result.json`（list/info 另存 `app.json`） |
| `file` | 文件传输：`send` / `recv` / `exist` / `delete`（本地侧必须落在工作区内） | `deveco-<n>/result.json` |
| `uiassert` | 确定性 UI 断言：`present` / `absent` / `count`，基于 `ui find` / `ui wait`，**不是视觉模型猜测** | `uiassert.json` + `output.log`，通过时可作 observation |
| `trace` | `hdc shell hitrace` 抓原始 trace（默认分类 `ability graphic ace app`，可用 `categories` 覆盖）；**只抓原始数据，不做 fps/jank 判定**；hitrace 报错时（即使 hdc 退出码为 0）判失败并列出可用分类 | `trace.txt`，通过时可作 observation |
| `project` | 只读解析 `build-profile.json5` / `AppScope/app.json5` / `module.json5` / `oh-package.json5` 与磁盘 HAP 产物 | `project.json`（不执行任何命令） |
| `api` | 只读查询本机 SDK `.d.ts`：模块解析、`@since` / `@deprecated` / `@syscap` 等标签、声明片段；`op=versions` / `list` | `api.json` / `sdk-modules.json`（不执行任何命令） |
| `compat` | `devecocli check compat`：源 SDK 版本 → 目标版本兼容性检查；`op=versions` 列可用版本 | `compat.json` |

## 什么时候用哪个

- **想确认「设备/模拟器现在是什么状态」**：`emulator op=list`、`app op=list`、`app op=foreground`。
- **想在验收前把 UI 事实固定下来**：`uiassert selector="text=登录" expect=present`，把 `uiassert.json` 写进审计 `checks[].evidenceFiles`。
- **性能判据需要原始素材**：`trace duration=5 categories="ability graphic ace app"`（默认就是这四个分类），`trace.txt` 作为原始证据；fps/jank 结论仍要单独测量。注意 hitrace 的退出码不可信——分类写错时它仍返回 0，插件会按输出里的 `error:` 判失败并列出可用分类。
- **审计报告需要工程事实**：`project` 输出 bundleName / SDK 版本 / 模块 / Ability / 权限 / 页面 / 产物。
- **需要 `@since` / `@deprecated` 这类 SDK 事实**：`api module=@ohos.promptAction name=showToast`。
- **想验证 API 兼容性**：`compat`（缺省从工程 `build-profile.json5` 推断 source/target；也可 `op=versions` 先看可用版本）。

## 配置

新增一个可选项：

```yaml
- id: dwguard-hmos
  config:
    harmonySdkPath: ''   # 空 = 自动探测 DEVECO_SDK_HOME / HOS_SDK_HOME / DevEco Studio 默认目录
```

`api` / `compat` 的工程推断会把工作区里唯一的 DevEco 工程（含
`build-profile.json5`）识别为工程根；`project` 的 `path` 必须在工作区内。

## 边界

- `uiassert` 通过 ≠ 验收通过：它只是把「某个选择器存在/消失/数量」固定成证据，
  四维验收仍由 `dwguard_audit` 判定。
- `trace` 只负责抓取；性能结论（fps/jank/启动耗时）需要独立测量值。
- `project` / `api` 只读：不构建、不执行 CLI、不下载任何东西。
- `file` 的本地侧限制在工作区内（`send` 的源、`recv` 的目标），避免证据文件散落。
- `emulator start` 冷启动可能超过单次超时；建议 `background: true`，然后用 `jobs`
  查看日志，等 `device list` 出现设备后再继续。
