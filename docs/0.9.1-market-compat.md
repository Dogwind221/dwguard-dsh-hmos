# 0.9.1：为什么插件没出现在 DSH Market

## 结论

插件**已经在目录里**（awesome-dsh-plugin 条目 `Dogwind221__dwguard-dsh-hmos.yml`，PR #11395 已合并），npm 包也存在。市场不显示的原因是**兼容性预检把 0.8.8/0.9.0 判成了不兼容**，不是目录缺失。

## 根因

0.9.0 的 `package.json`：

```json
"peerDependencies": {
  "@deepseek-ai/dsh-tools": "0.2.1-rc.5"
}
```

dsh-market 的发现逻辑会对声明在 `@deepseek-ai/dsh-*` 上的 peer 做主机版本比较；当前主机是 DSH `0.2.2-rc.1`。精确版本 `0.2.1-rc.5` 低于主机版本，被判为：

```text
status: incompatible
requirement: >=0.2.1-rc.0 <0.3.0 ∩ 0.2.1-rc.5
```

所以即使目录里有条目，市场也会隐藏/拒绝它。

## 修复

```json
"peerDependencies": {
  "@deepseek-ai/dsh-tools": "^0.2.1-rc.5"
}
```

0.9.1 起，用 dsh-market 的真实 `deriveHostCompatibility()` 复核：

```text
0.9.1 status=compatible
requirement=">=0.2.1-rc.0 <0.3.0 ∩ ^0.2.1-rc.5"
```

## 验证命令

```powershell
node --test tests/market-compat.test.mjs
```

0.9.2 起测试直接断言真实 verdict 矩阵（semver prerelease），不再依赖
`_probe/market-check-npm.mjs`；那个 probe 是本地开发辅助，不在 npm 包里。

期望：

- `0.2.1-rc.5` → compatible
- `0.2.2-rc.1` → compatible
- `0.1.2` → incompatible
- `0.3.0-rc.1` → incompatible
- 旧精确 pin 在 `0.2.2-rc.1` → incompatible

## 目录刷新

- 目录数据源：`awesome-dsh-plugin/awesome-dsh-plugin`
- 市场索引包：`dsh-plugin-catalog`（每日生成）
- 0.9.1 发布后，索引需要下一次刷新才会把 **0.9.1** 作为可安装版本列出来；在此之前市场可能仍缓存 0.8.8 的旧兼容结论。
- 刷新后重开市场/清缓存再搜索 `dwguard-dsh-hmos`；若仍不显示，检查市场“只显示兼容插件”筛选。
