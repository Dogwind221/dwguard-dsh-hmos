# 0.8.0 计划：AI Native Harness 三项基础

> 状态：**已实现（0.8.0）** · 目标版本 `0.8.0` · 前置 `0.7.1`
> 范围：恢复能力、规模化知识/SOP、执行链闭环。**App 侧 AI（Intent/端侧模型/应用内智能体）明确不做**；移动端不是开发运行时。

## 1. 恢复能力：run state / checkpoint / resume / retry / fallback

现有 `.shared/state.json` 只存计数与阶段提示，`dwguard_status` 从产物反推阶段；它不能回答：

- 上次做到哪一步、证据是什么；
- 中断后从哪里继续；
- 同一阶段失败几次、何时转人工；
- `devecocli` 不可用时下一条执行路径是什么。

0.8.0 增加 `.shared/harness/run.json`：

```jsonc
{
  "schemaVersion": 1,
  "runId": "run-...",
  "iteration": 1,
  "specVersion": 1,
  "phase": "executing",
  "status": "running | blocked | done",
  "checkpoints": [
    { "id": "cp-1", "at": "...", "phase": "executing", "step": "pipeline", "note": "...", "evidence": ["artifacts/..."] }
  ],
  "attempts": { "pipeline": 1, "audit": 0 },
  "lastError": { "step": "pipeline", "message": "...", "at": "..." },
  "nextAction": "...",
  "updatedAt": "..."
}
```

工具 `dwguard_harness`：

- `status`：当前 run、阶段、checkpoint、attempts、next；
- `checkpoint`：记录当前阶段/步骤/证据；
- `resume`：跨会话读取 checkpoint，核对 specVersion/iteration，给出续跑步骤；
- `retry`：同一 step 尝试次数 +1，超过 `harnessMaxRetries`（默认 3）转 `blocked`/人工；
- `fail`：记录错误与阶段，返回 fallback / 人工；
- `fallback`：返回 `devecocli → deveco-mcp → hdc+hvigor` 的降级链与当前档位；
- `close`：标记 done。

验收：新建 tool 实例能 resume 上一个实例的 checkpoint；retry 超限不再返回 retry；fallback 记录档位；损坏 run.json 可修复。

## 2. 规模化知识 / SOP

目标不是“再写 32 条规则”，而是把**工程知识与可执行 SOP** 变成可检索资产：

```text
knowledge/
├─ engineering.json   # 32 条：现象/原因/检查/关联规则
└─ sops.json          # 14 个：阶段/输入/步骤/门禁/证据
```

14 个 SOP 覆盖：环境就绪、需求澄清、架构设计、任务拆解、编码实现、构建与签名、安装启动、功能验证、审美/UI 取证、无障碍、性能、回归、发布/AGC、缺陷/热修。

32 条工程知识覆盖：spec/证据/预审、构建/签名/安装、布局树/截图、无障碍、性能、深色/折叠屏/字体、状态管理、列表、导航、生命周期、并发、网络、存储、权限/隐私、发布、日志/PII、崩溃、设计 token、对比度、动效、i18n、回滚。

`dwguard_knowledge` 扩展：

- `action: "sops"`：按 `query`/`phase` 搜索 SOP；
- `action: "sop"`：按 `id` 取一个 SOP 的完整执行卡；
- `action: "engineering"`：搜索 32 条工程知识；
- 默认仍是 `sediment`，兼容旧调用。

## 3. 执行链闭环

`dwguard_deveco` 新增：

- `sign`：`devecocli signature generate`（若 CLI 版本不支持，明确失败并给 fallback）；
- `pipeline`：按 `sign → build → run → screenshot → layout` 顺序执行（真实 CLI 验证发现签名配置写入后必须重新构建），每步写：
  - 命令、退出码、stdout/stderr；
  - `artifacts/deveco-<n>/pipeline.json`；
  - 失败即停，不继续跑后续步骤；
  - `resume: true` 跳过上一次已成功步骤（按 step + specVersion 匹配）；
  - 找不到 CLI / 设备离线时返回 `devecocli → mcp → hdc+hvigor` 的降级提示与已保留现场。

`pipeline` 不是“自验通过”：截图/布局树仍要交给 `dwguard_audit` 做外部验收。

真实 CLI/设备验证见 [0.8.0-verification.md](0.8.0-verification.md)。pipeline 现在会自动尝试
`devecocli → deveco-mcp → hdc+hvigor`，每档 attempt 写入 pipeline 记录；hdc 截图/布局适配器
已在 Pura 90 模拟器实测。

### 3.1 持久队列 / worker

- `dwguard_harness` 的 `enqueue/queue/claim/complete/task-fail` 写 `.shared/harness/queue.json`；
- claim 带 lease，过期可被其他 worker 回收；
- `scripts/harness-worker.mjs --workspace ... --command ...` 可由 Windows Task Scheduler/cron
  定时领取，不再依赖人再开一轮；
- worker 只是执行 `--command`，具体 agent/命令由调用方提供。

## 4. 多机 / 多项目

- run state 与 pipeline 都按 workspace 的 `.shared` 隔离，不写全局共享状态；
- 设备侧仍走现有 `.device-lock.json` 串行锁，避免多项目同时抢同一设备；
- 不新增“跨机器共享 run state”的分布式协调；App 侧 AI 与移动端开发运行时不在范围。

## 5. 验收标准

| ID | 判据 | 验证 |
| --- | --- | --- |
| HR-1 | checkpoint 跨 tool 实例可读；resume 返回同一 checkpoint 与 next | 单测：两个 tool 实例 |
| HR-2 | retry 超过上限返回 blocked/人工，不再 retry | 单测 |
| HR-3 | fail/fallback 记录阶段与降级档位，不丢现场 | 单测 |
| KN-1 | sops 可列出 14 个、按 query/phase 命中；sop 可取完整步骤 | 单测 |
| KN-2 | engineering 可搜 32 条，且每条带检查方法与关联规则 | 单测 |
| EX-1 | pipeline 按 build/sign/run/screenshot/layout 顺序调用，失败即停 | 单测：fake runner |
| EX-2 | pipeline 写每步证据；resume 跳过已成功步骤 | 单测 |
| EX-3 | CLI 缺失/失败返回 fallback，不伪造成功 | 单测 |
| EX-4 | pipeline 结果不直接当验收通过；仍由 audit 判定 | 代码检查 + 文档 |

## 6. 不做什么

- 不做 App 侧 AI（Intent/端侧模型/应用内 Agent）；
- 不把移动端当开发运行时；
- 不做跨机器分布式 run state；
- 不把 pipeline 的截图/布局树当验收结论；
- 不在没有确认的情况下自动改签名/发布配置。
