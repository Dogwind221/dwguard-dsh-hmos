# 1.0.1 — DevEco Code CLI 零点击执行（`dwguard_code`）

1.0.1 补上「DSH 派发 → 执行器启动」之间的最后一环：不再需要把
`tasks/goal-brief.md` 手动粘贴进 DevEco Code 的 Goal 模式，DSH 可以自己把冻结
简报交给 DevEco Code CLI（`deveco run`）在后台执行，并把事件流与 job 状态落盘。

> 执行器只产出**证据**。验收仍然由 `dwguard_audit` 独立取证后判定；执行器自述
> 永远不是 `pass`。

## 前置条件

```bash
npm install -g @deveco/deveco-code
deveco --version
deveco auth login
```

二进制名是 **`deveco`**（不是 `deveco-code`）。它需要在 `PATH` 上，或通过
`devecoCodePath` 指定绝对路径。

## 配置

```yaml
- id: dwguard-hmos
  config:
    devecoCodePath: ''        # deveco 路径；空 = PATH / npm 全局
    codeProjectDir: ''        # 工程根目录；空 = 当前工作区
    codeModel: ''             # 可选 provider/model
    codeAgent: ''             # 可选 deveco agent 名称
    codeAuto: false           # true = 给 deveco run 传 --auto
    codeTimeoutMinutes: 45    # 单次运行超时（1–240 分钟）
```

`codeAuto` 默认 **false**：不传 `--auto`，保留交互审批。只有明确开启后才会自动
批准「未被拒绝的工具」。

## 工具动作

```text
dwguard_code action="run" dir="D:/project"       # 启动后台 job，返回 job id
dwguard_code action="status" id="code-1"         # 查看状态（省略 id = 最近一个）
dwguard_code action="stop" id="code-1"           # 停止（终止进程树）
dwguard_code action="list"                       # 列出所有 job
```

`run` 会：

1. 读取 `tasks/goal-brief.md`（必须先 `dwguard_dispatch` 生成）；
2. 在 `dir`（默认工作区）后台启动
   `deveco run --dir <dir> --format json [--auto] [--model …] [--agent …] <prompt>`；
   prompt 只引用简报文件路径，长简报不会撞 Windows 命令行长度限制；
3. 把 stdout 的 JSON 事件逐行写入 `artifacts/code-<n>/events.jsonl`；
4. 把 job 状态写入 `artifacts/code-<n>/meta.json`（pid / status / exitCode /
   sessionID / eventCount / lastText / lastError）。

## 边界与约定

- **只启动冻结任务包**：`requireSpec` 校验失败、没有 Goal 简报时直接拒绝；
- **单工程目录单 job**：同一目录已有运行中 job 时拒绝再启动（含跨会话的
  `meta.json` 检测）；
- **默认 45 分钟超时**：超时后终止进程树，状态记为 `timeout`；
- **job 表在插件实例内存中**，但 `status` / `stop` / `list` 会回退读取
  `artifacts/code-<n>/meta.json`，DSH 重启后仍能查到历史 job；
- **执行器输出不是验收**：跑完后照常 `dwguard_scan` / `dwguard_audit` 取证。
