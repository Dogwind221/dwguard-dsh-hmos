# 0.9.2：0.2.2 运行时 peer 与启动验证

## 实际 boot 的宿主

```text
DSH CLI:          0.2.2-rc.1
dsh-tools:        0.2.2-rc.1
cordis:           4.1.0
schemastery:      3.19.0
```

## package 声明

```json
"peerDependencies": {
  "@deepseek-ai/cordis": "~4.0.5 || ~4.1.0",
  "@deepseek-ai/dsh-tools": "^0.2.1-rc.5",
  "@deepseek-ai/schemastery": "~3.18.5 || ~3.19.0"
},
"devDependencies": {
  "@deepseek-ai/cordis": "4.1.0",
  "@deepseek-ai/dsh-tools": "0.2.2-rc.1",
  "@deepseek-ai/schemastery": "3.19.0"
}
```

`dsh-tools` 保持 caret：对 market 而言 0.2.1-rc.5、0.2.2-rc.1 兼容，
0.3.0-rc.1 不兼容。手写 `>=0.2.1-rc.5 <0.3.0` 在 `includePrerelease` 下会
错误放行 0.3.0-rc.1，所以不用它。

## 验证

### 编译期

```text
npm run typecheck  # 0 errors, against dsh-tools 0.2.2-rc.1
npm run build      # 0 errors
```

### 真实 market 判决

`tests/market-compat.test.mjs` 用 `semver.satisfies(..., {
includePrerelease: true })` 断言：

| 宿主 | 当前 manifest |
| --- | --- |
| 0.2.1-rc.5 | compatible |
| 0.2.2-rc.1 | compatible |
| 0.1.2 | incompatible |
| 0.3.0-rc.1 | incompatible |

旧精确 pin `0.2.1-rc.5` 在 0.2.2-rc.1 上不兼容。

发布后用 dshmarket 1.71.1 的真实 `deriveHostCompatibility()` 对 npm
`dwguard-dsh-hmos@0.9.2` 复核，结果与测试一致：0.2.1-rc.5 / 0.2.2-rc.1
compatible，0.1.2 / 0.3.0-rc.1 incompatible。

### boot

使用临时 profile `boot022b`（从 headless 模板创建），安装**已发布**的 npm 包：

```powershell
dsh --profile boot022b --from-default-profile headless --dump-config
dsh plugin --profile boot022b add dwguard-dsh-hmos@0.9.2
dsh --profile boot022b headless "只回复 BOOT-OK-0.9.2，不要调用任何工具。"
```

结果：

- profile 中存在 host 行：`# == dwguard-dsh-hmos / id: dwguard-hmos`；
- 安装到 `dwguard-dsh-hmos@0.9.2`；
- 启动成功，模型返回 `BOOT-OK-0.9.2`，退出码 0；
- 没有插件加载/导入错误；
- 使用当前用户的 DEEPSEEK_API_KEY 启动，不写入仓库或日志。

这条证据只证明 **DSH 0.2.2-rc.1 能加载并运行已发布的 0.9.2 bundle 的基本会话**；
它不代表物理设备、UI 或四维验收证据已经通过。

## 待复核
