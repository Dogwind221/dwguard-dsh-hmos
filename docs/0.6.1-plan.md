# 0.6.1 计划：审美学习 v1

> 状态：**已实现（0.6.1，见 `CHANGELOG.md` 与 `tests/aesthetic.test.mjs` 的 AEST-A~K）** · 目标版本：`0.6.1` · 前置：`0.6.0`（设备矩阵）、`0.5.0`（断言化）
> 范围：审美偏好档案 / 视觉基线 / 学习闭环 / 新工具 `dwguard_aesthetic`。

## 0. 为什么

功能/性能/无障碍可以靠断言和数值回归；审美判据（`DW-AES-*` 21 条：间距、圆角、字号阶、配色、密度、动效、深色、图标、卡片）每轮重新争论：

- 用户确认过的审美选择没有记录；
- 截图对比靠肉眼，没有基线，「这轮比上轮丑了」无法回归；
- `dwguard_calibration` 的 miss 只统计漏检率，不反哺规则。

目标：**审美判断有档案、有基线、能从用户反馈中学习，而且全程可解释、可撤销。**

---

## 1. 输入（学什么）

| 来源 | 例子 | 权重 |
| --- | --- | --- |
| 用户确认（`dwguard_confirm` accept） | "圆角用 20 更柔和" | 0.7 起步 |
| 用户驳回/返工理由 | "间距太挤了，改回 16" | 0.4（反向证据） |
| 审计审美 finding（用户接受） | `A-01` 间距 20vp 偏离基线 | 0.5 |
| `dwguard_calibration miss`（审美维） | "审计通过但用户觉得丑" | 0.6（风险条目） |
| 项目资源文件（冷启动种子） | `resources/base/element/color.json` / `float.json` | 0.6 |

**不学**：聊天里的随口评价、没有 `source` 的自由文本、执行者自述。

## 2. 存储（三份文件）

```text
knowledge/
  aesthetic-profile.md        # 人类可读表格 + JSON 块（机器可读）
  aesthetic-history.jsonl     # 追加式事件：proposed/applied/superseded/conflict
artifacts/visual-baseline/
  <specVersion>/
    index.json                # 页面/状态 → 文件 + 关键数值
    <page>.<state>.png        # 截图（人复核）
    <page>.<state>.bounds.json# 布局树数值：节点 id/bounds/fontSize/padding/radius/color
```

档案条目（JSON 块）：

```jsonc
{
  "id": "AES-RADIUS-01",
  "area": "radius",                 // palette|spacing|radius|type|density|motion|dark|icon|card
  "decision": "卡片圆角 20vp",
  "value": { "number": 20, "unit": "vp" },
  "source": "confirmation-3",
  "evidence": ["artifacts/visual-baseline/3/index.json"],
  "confidence": 0.7,                // 0–1
  "status": "active",               // active|superseded
  "updatedAt": "2026-11-02T…"
}
```

## 3. 提取规则（确定性，不靠模型猜）

`dwguard_aesthetic learn` 对每轮输入做一次确定性抽取：

1. **数值**：正则 `(\d+(?:\.\d+)?)\s*(vp|dp|px|pt|ms|%|deg)?`；**颜色**：`#[0-9A-Fa-f]{6}`；
2. **领域映射**：色/主色/强调色/品牌色 → `palette`；间距/留白/margin/padding/gap → `spacing`；圆角/radius → `radius`；字号/字重/行高 → `type`；密度/紧凑/宽松 → `density`；动效/时长/缓动/ms → `motion`；深色/暗色/夜间 → `dark`；图标 → `icon`；卡片/列表行 → `card`；
3. **候选合并**：同 `(area, 值, 单位)` 只留一条，`confidence` 按 §5 累加；同 area 不同值 → 生成 `conflict` 提议（列出新旧值与来源），**不覆盖**；
4. **冷启动**：无档案时先读项目 `resources/base/element/color.json` / `float.json`，抽 `palette` / `spacing` / `radius` 作种子（`source: "project-resources"`，confidence 0.6）。

## 4. 提议 → 用户确认 → 应用

```text
learn（默认）: 只返回 proposals，不写文件
   { proposals: [ {id, area, decision, value, confidence, reason, sources[]} ],
     conflicts: [ {area, candidates[{value, sources}], question} ] }

apply:true（必须带用户确认）:
   - 无冲突条目：写档案（新条目或 confidence 累加）
   - 冲突条目：要求用户在对话里选一个（apply 带 choice），落选值标 superseded
   - 追加 aesthetic-history.jsonl，版本号 +1
```

## 5. 置信度规则

- 确认 +0.1、驳回 −0.2、重复证据 +0.05；夹在 0–1；
- ≥0.8 视为"稳定偏好"（spec 默认引用），<0.3 保留但不推荐。

## 6. 消费（学完之后怎么用）

1. **写任务包（`dwguard_spec`）**：审美判据可带 `profileRef: "AES-RADIUS-01"`；对同 area 偏好给出提示（`W_AEST_PROFILE_HINT`），只建议不代写；
2. **审计（`dwguard_audit`）**：审美 check 可引用 `profileRef`；`profileRef` 不存在 → 闸门 error；`compare` 输出直接作为 `actual`（如 `"圆角 20vp"`），配 `assertion: { matcher: "range", min: 18, max: 22, unit: "vp" }`；
3. **确认（`dwguard_confirm`）**：accept 后的 `next` 提示用 `learn` 记录本轮审美取舍（不自动 apply）；验收报告以「审美档案」列 + 「审美基线差异」小节承载增量；
4. **下一轮**：`compare` 用新基线 + 档案判据回归；用户改口时旧条目 `superseded`，历史可追溯。

## 7. 基线回归（不靠图像库）

- `baseline save`：**只允许在「有通过审计 + 用户确认」之后**，把截图与 `bounds.json` 存进 `artifacts/visual-baseline/<specVersion>/`；
- `compare`：对同一页面/状态读当前 `bounds.json` 与基线比较：
  - 间距/圆角：±2vp 内通过，超出按倍数定 `major`/`minor`；
  - 字号：0 容忍；
  - 颜色：hex 精确比较（token 归一化后）；
  - 截图：sha256 不同即提示"需人工并排复核"，不当自动失败；
- 基线版本与当前 `specVersion` 不一致时输出警告（设计改版要显式重建基线）。

## 8. 完整示例

> 第 2 轮用户确认时顺口说：「卡片圆角 16 太方了，用 20，间距保持 12。」

1. `learn` 抽取 `radius=20vp`（确认，0.7）、`spacing=12vp`（确认，与已有 12 合并 → 0.8）；
2. 返回 proposals，不落盘；
3. 用户确认后 `apply:true`：档案新增 `AES-RADIUS-01=20vp`、`AES-SPACING-01=12vp(0.8)`；
4. 下一轮 `dwguard_spec`：提示 `W_AEST_PROFILE_HINT`，建议 `A-02 卡片圆角 20vp（profileRef AES-RADIUS-01）` + `assertion range 18–22 vp`；
5. `dwguard_audit`：审美子代理跑 `compare`，`actual="20vp"`，断言通过；报告写「profileRef AES-RADIUS-01 · 基线一致」；
6. 若下轮改成 24vp：`compare` 超差 → finding；用户说"24 更好" → `learn` 出 conflict，用户选 24 → 20 标 superseded，历史留痕。

## 9. 工具 `dwguard_aesthetic`（第 14 个工具）

| action | 作用 | 约束 |
| --- | --- | --- |
| `profile` | `list` / `get` / `write` / `remove` 审美档案 | 写入必须带 `source`+`confidence`；remove 只标 superseded |
| `baseline` | `save` / `list` 视觉基线 | save 需通过审计 + 用户确认 |
| `compare` | 当前证据 vs 基线，输出数值 diff | 只读；输出可直接作 `actual` |
| `learn` | 从本轮输入提议档案增量/冲突 | 默认不落盘；`apply:true` 才写 |

## 10. 验收标准（可证伪）

| ID | 判据 | 验证方式 |
| --- | --- | --- |
| AEST-A | 档案写入/读回字段完整（id/area/decision/value/source/confidence/status） | 单测：写读一致 |
| AEST-B | `learn` 默认不落盘（档案 sha256 不变），只返回 proposals | 单测 |
| AEST-C | 置信度规则：确认 +0.1 / 驳回 −0.2 / 重复 +0.05，夹 0–1 | 单测：多轮加减 |
| AEST-D | 同 area 不同值 → 返回 conflict，不覆盖旧值 | 单测 |
| AEST-E | `apply` 冲突必须带 `choice`，落选值标 superseded 且写 history | 单测 |
| AEST-F | `baseline save` 缺「通过审计 + 用户确认」→ 拒绝 | 单测 |
| AEST-G | `compare` 阈值：间距/圆角 ±2vp、字号 0、颜色精确；超差出 fail 列表 | 单测：构造 bounds 差异 |
| AEST-H | `spec` 引用不存在的 `profileRef` → 审计闸门 error | 单测 |
| AEST-I | 冷启动从项目 `color.json/float.json` 抽种子（palette/spacing/radius） | 单测：最小资源样例 |
| AEST-J | 报告渲染 `profileRef` 与基线差异列 | 单测：markdown 断言 |
| AEST-K | 档案无 `source` 的写入被拒绝（防"模型自嗨"） | 单测 |

## 11. 不做什么

- 不做像素级审美评分（放到更后面的版本，可选像素 diff）；
- 不用模型自动改用户需求/判据；
- 不跨项目共享审美偏好（项目级档案；跨项目复制需手动）；
- 不把"用户没说的话"当偏好（无 source 不写）。

## 12. 兼容性与风险

- 审美档案/基线是新增目录；`profileRef` 可选字段；工具数 13 → 14；
- 风险：档案变成"个人口味大杂烩" → area/source/confidence + 用户裁决；
- 风险：基线过期 → 按 `specVersion` 隔离 + 版本不一致警告；
- 风险：学习不可解释 → 所有提议带 source/evidence，history 追加式、可 supersede 不删除。
