# 1.0.3 — 取证闭环（Forensics loop）

1.0.3 把「验收取证」再往前推一步：把崩溃、日志、UI 指纹、废弃 API 变成**可结构化引用的证据文件**，并让 `dwguard_audit` 自动复核 UI 断言结果。

工具数仍是 **17**，`dwguard_deveco` 的动作数仍是 **25**（只扩参数与子动作）。

## 1. `log` 扩展：`op=crash` / `op=hilog`

### `op=crash`

```jsonc
{ "action": "log", "op": "crash", "device": "127.0.0.1:5555" }
```

- 命令：`devecocli log --crash [--device ...] [--path ... --format json|report]`（`--format` 只在配合 `--path` 时可用；设备实时日志不带它）。
- 解析：`src/forensics.ts` 支持 JSON 与 faultlog 文本，识别 **jscrash / cppcrash / appfreeze**，提取：
  - `pid`、`process`、`bundle`、`faultTime`、`reason`、`signal`
  - `frames`（最多 32 条）与 `topFrame`（栈顶帧）
- 证据：`artifacts/deveco-<n>/crash.json`，形如：

```json
{
  "schemaVersion": 1,
  "capturedAt": "…",
  "device": "127.0.0.1:5555",
  "reports": [
    { "type": "cppcrash", "pid": 4321, "topFrame": "#00 pc … libace.z.so", "frames": ["…"] }
  ]
}
```

- 没有解析到记录时也返回 `ok`（设备本来就没有崩溃），摘要为 `crash：未解析到 crash 记录`——**不要把"无崩溃"误当"有证据"**。

### `op=hilog`

```jsonc
{ "action": "log", "op": "hilog", "device": "127.0.0.1:5555",
  "args": "--tail 500", "level": "E", "bundle": "com.demo.app",
  "regex": "Failed|exception", "pid": 4321 }
```

- 命令：`devecocli log [--level X] [--bundle-name X] [--device ...]`，其他过滤参数（`--keyword` / `--tail` / `--from` / `--to`）通过 `args` 追加。
- `regex` 与 `pid` 是**插件侧过滤**（不传给 CLI），便于把范围缩到一次取证窗口。
- 折叠算法（确定性）：十六进制 → `<hex>`，UUID → `<uuid>`，4 位以上/普通数字 → `<n>`，压缩空白；按模板计数排序。
- 证据：`hilog-summary.json`：

```json
{
  "total": 199, "matched": 46, "levels": { "I": 153, "W": 20, "E": 26 },
  "pids": [{ "pid": 787, "count": 61 }],
  "tags": [{ "tag": "C02c02/PARAM", "count": 9 }],
  "folded": [{ "pattern": "…", "count": 7, "levels": ["W","E"] }],
  "errors": [{ "pattern": "…", "count": 46, "sample": "…" }],
  "firstTimestamp": "11-22 17:53:20.202", "lastTimestamp": "11-22 17:53:39.737"
}
```

> 实测（Mate X7 模拟器，HarmonyOS 6.1.1，`--tail 200`）：199 行、46 条错误、30 类模板。

## 2. `uiassert`：`device=all` + `fingerprint`

### `expect=fingerprint`

- 采集：`{ "action": "uiassert", "expect": "fingerprint" }` → 运行 `ui layout --format json --mode full`，把布局树归一化后计算 `fp-<16 hex>`。
- 归一化规则：保留 `id / type / text / accessibilityId / accessibilityText / clickable / enabled / checked / selected / focusable / scrollable` 与**子节点顺序**；**丢弃 bounds 坐标**，因此同一结构在不同分辨率/折叠态下应得到同一指纹。
- 复核：`{ "action": "uiassert", "expect": "fingerprint", "fingerprint": "fp-…" }`；不一致时 `ok=false`，并在 `uiassert.json` 里记录实际指纹。
- 指纹不替代布局坐标类判据：它只证明“结构/文案没变”，间距、圆角仍要用 bounds 断言。

### `device=all`

- 需要配置 `device.pool`（每项 `{ sn, family, apiIndex? }`）。
- 逐台串行执行同一断言（每台独立设备锁），输出 Markdown 表格 + `uiassert-matrix.json`：

```json
{
  "schemaVersion": 1, "expect": "present", "passed": false,
  "passedCount": 1, "total": 2,
  "results": [
    { "device": "S1", "family": "phone", "passed": true, "actual": "exit 0 · matches 1" },
    { "device": "S2", "family": "tablet", "passed": false, "actual": "exit 1 · matches 0" }
  ]
}
```

- 每台设备另写 `uiassert-<i>-<sn>.json` 与 `output-<i>.log`；通过的设备各生成一个 observation，可作为 audit 的 `actual.observationRef`。
- `device=all` 不改变单台语义；单台仍写 `uiassert.json`。

## 3. `api op=scan`：废弃 API 引用扫描

```jsonc
{ "action": "api", "op": "scan", "path": "." }
```

- 扫描工程内 `.ets/.ts/.tsx/.js/.mjs/.cjs`（跳过 `node_modules/oh_modules/build/.hvigor/...`，单文件 ≤512KB，最多 400 个）。
- 提取 `@ohos.*` / `@kit.*` 导入 → 读取对应 SDK `.d.ts` 的 `@deprecated` 声明 → 在源码里找调用点（跳过 import 行与 `//` 注释）。
- 证据：`api-scan.json`：

```json
{
  "projectRoot": "…", "filesScanned": 12, "imports": ["@ohos.demo"],
  "deprecatedSymbols": 3,
  "findings": [{ "file": "entry/src/main/ets/pages/Index.ets", "line": 4, "symbol": "foo", "module": "@ohos.demo", "deprecated": "since 20 use bar()" }]
}
```

- **零命中也是结果**：把 `api-scan.json` 写进兼容性判据的 `evidenceFiles`，同时保留扫描范围（filesScanned / imports）作为可复核事实。

### 兼容性判据模板（可直接写进 `dwguard_spec`）

```jsonc
{
  "id": "X-02",
  "dimension": "accessibility",
  "statement": "工程源码不引用任何 @deprecated SDK API",
  "verify": "dwguard_deveco action=api op=scan；api-scan.json 的 findings 长度为 0",
  "weight": "must",
  "assertion": { "matcher": "equals", "expected": 0 }
}
```

（`assertion` 的实测值取 `api-scan.json.findings.length`；若扫描范围为空，先补 `filesScanned > 0` 的辅助断言，避免“空扫描=通过”。）

## 4. `dwguard_audit`：uiassert 证据自动复核

- 当 `checks[].actual.observationRef` 指向 `action: "uiassert"` 的 observation 时，审计读取其中的 `uiassert.json`（或 matrix 文件）：
  - `passed !== true` → 审计直接失败（`uiassert 证据校验失败`），不会进入四维闸门；
  - matrix 要求 `results` 全部 `passed === true` 且 `passed === true`。
- 当 `checks[].evidenceFiles` 里包含 `uiassert.json` / `uiassert-matrix.json` / `uiassert-<i>-<sn>.json` 时，同样自动复核 `passed`。
- 这样"半自动取证"闭环为：`uiassert` → observation/evidence → `audit` 自动复核，不需要人工把断言结论抄进检查项。

## 5. 边界

- `crash` 解析是 best-effort：不同 HarmonyOS 版本的 faultlog 字段略有差异；解析不到时保留原始 `output.log`，不要把"没解析到"当成"没有崩溃"。
- `hilog` 折叠会合并数字/十六进制差异；排查具体一行时用 `regex` 缩小范围并看 `output.log`。
- 指纹只覆盖结构/文案；颜色、间距、圆角、动效仍需截图/布局树/数值断言。
- `api scan` 是静态引用扫描，不等于运行时兼容性证明；`devecocli check compat` 仍用于 SDK 级兼容检查。
