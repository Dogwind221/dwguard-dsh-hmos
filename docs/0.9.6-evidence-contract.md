# 0.9.6：非破坏式证据契约

状态：**实现完成（本地，未推送）**

目标：给四维审计增加类型化证据和覆盖率，但**不改已有任务包/审计报告的默认行为**。

## 1. requiredEvidence（可选）

`dwguard_spec` 的判据可以新增：

```json
{
  "id": "A-02",
  "dimension": "aesthetic",
  "requiredEvidence": ["screenshot_before", "screenshot_after", "layout_tree"]
}
```

允许的类型：

```text
screenshot / screenshot_before / screenshot_after
layout_tree / hilog / measurement / video / a11y_tree / text
```

旧任务包没有该字段：完全按旧逻辑运行，不会突然要求前后截图。

## 2. evidenceRefs（可选）

`dwguard_audit.checks[]` 可以给 `evidenceFiles` 里的文件标类型：

```json
{
  "criterionId": "A-02",
  "result": "pass",
  "evidence": "改前/改后截图与布局树已核对",
  "evidenceFiles": ["artifacts/before.png", "artifacts/after.png", "artifacts/layout.json"],
  "evidenceRefs": [
    { "path": "artifacts/before.png", "kind": "screenshot_before" },
    { "path": "artifacts/after.png", "kind": "screenshot_after" },
    { "path": "artifacts/layout.json", "kind": "layout_tree" }
  ]
}
```

`evidenceRefs.path` 必须同时出现在 `evidenceFiles` 里，否则证据不会进证据包，闸门会报错。

`evidenceFiles` 仍是 `string[]`，没有改类型；`evidenceRefs` 只是可选的类型化视图。

## 3. 缺证据 → unverified

如果判据声明了 `requiredEvidence`，但检查没有提供对应类型：

```text
check.result = pass
requiredEvidence = screenshot_before
evidenceRefs 只有 screenshot_after
→ 审计前自动降级为 unverified
→ must 判据不能通过
```

这不是新状态：复用现有 `unverified` 和现有 must 闸门。

## 4. coverage.evidence（可选）

现有 `coverage` 保持不变：

```json
{
  "total": 4,
  "passed": 4,
  "failed": 0,
  "unverified": 0,
  "missing": [],
  "evidence": {
    "required": 3,
    "satisfied": 3,
    "missing": []
  }
}
```

只有任务包声明了 `requiredEvidence` 时才出现 `evidence`；旧审计 JSON 没有这个字段。

## 5. checker（只读）

新增：

```powershell
node bin/dwguard.mjs checker --workspace <项目>
```

它只读 `spec.json` 和最新的 `audit-<n>.json`，输出：

- 哪些判据缺 requiredEvidence；
- evidenceRefs 是否都列入 evidenceFiles；
- evidence coverage `n/m`。

它**不写** acceptance/rework，不改 `gate.pass`，不是第二个验收闸门。只是独立 notes 工具。

## 6. before/after

`0.9.6` 只增加类型：

```text
screenshot_before
screenshot_after
```

不自动要求所有审美判据都提供。只有在任务包里显式写 `requiredEvidence` 的视觉变更判据才启用，例如：

```json
"requiredEvidence": ["screenshot_before", "screenshot_after"]
```

数值回归仍使用 `dwguard_aesthetic baseline/compare`；before/after 只负责视觉变化方向。

## 7. 兼容性

- 旧 `spec.json` / `audit-*.json` 没有新字段 → 不校验、不降级、不改报告字段；
- `evidenceFiles` 类型不变；
- `gateDelivery` 的旧规则不变；
- 新增字段全部可选；
- `schemaVersion` 仍为 1。
