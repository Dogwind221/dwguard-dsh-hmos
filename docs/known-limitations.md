# 已知限制（0.9.9 发布候选，0.9.2 行为基线）

> 版本归口：文档随 **0.9.9 P0 发布候选**落地；行为基线是 **0.9.2** 的已发布版本，并在 0.9.9 代码树上复核。
> 0.9.2 已经发布，不能把新文档回写成 0.9.2 的包内容；这里记录的是“0.9.2 起仍然成立的限制”。

## 1. CLIP live 调用

- **以图搜图**：未配置 CLIP、端点不可达或请求失败时，回退到 pHash + 颜色直方图，只做视觉相似，不做语义相似。
- **文本→图片**：`dwguard_design imageText` 依赖 CLIP 端点；端点未配置/失败时没有等价的离线语义 fallback，会直接报错或不可用。
- 不承诺 CLIP 延迟、可用性、配额或模型一致性；不同 endpoint/model 的向量不可混用。
- 相关缓存有模型/endpoint identity；换模型会失效重算，不是“永久可靠”的语义索引。

## 2. 自用规模

- 面向单用户、本地 `.shared`、本地文件桥的规模。
- 没有多租户隔离、租户配额、分布式锁或水平扩展。
- 没有做高并发/大 workspace/长时间压测；本地锁、队列和 lease 只保证单机范围内的一致性。
- 大数据量下的搜索、审计和 bridge 延迟没有生产级基线。

## 3. 无生产运维

- 没有监控、告警、备份、SLO、on-call、故障演练或容量规划。
- 没有高可用/多副本/灾备；`.shared` 的备份、保留和清理由使用者负责。
- 没有对 DSH 宿主、DevEco、设备或网络故障做 SLA 承诺。
- 不应把本插件当作生产发布流水线或生产服务的唯一控制面。

## 4. 物理设备基准

- 没有物理 HarmonyOS 设备时，`bench --device --require-physical` 返回 `blocked`（退出码 2）。
- 模拟器上的 build/screenshot/layout 通过，不等于物理设备通过；不伪造 physical 证据。
- 当前本机验证过 Pura 90 模拟器的 build/screenshot/layout；物理设备项仍是未覆盖。

## 5. 市场目录更新延迟

- npm 发布 ≠ DSH Market 立即出现；目录索引由 `dsh-plugin-catalog` 定期生成，存在缓存/日更延迟。
- 0.9.2 的兼容性修复已经发布，但市场能否显示还取决于索引刷新。
- 急用时应直接从 npm/本地 tarball 安装，不要等市场卡片。

## 6. 设计指南只存引用/摘要

- `docs/design-guide/index.json` 保存标题、URL、sha256、抓取日期、短摘要、章节索引和规则映射。
- **不保存**官方正文、图片、图标、模板、二进制资源。
- 摘要是定位和引用辅助，不是官方文档的替代品；以华为官方页面为准。
- 索引有抓取时间，官方文档更新后需要重新运行 `scripts/fetch-design-guide.mjs`。

## 7. 其他不应被误读的边界

- 0.9.2 市场修复只证明“兼容性判定通过”，不证明所有 DSH 版本/所有设备都可用。
- 设计入门清单绑定的是 `DW-AES-*` / `DW-A11Y-*` 的**可测代理**，不是“官方审美认证”。
- `dwguard_audit` 的通过只代表本轮任务包和证据通过，不代表代码库整体无缺陷。
- 没有任何 Go 运行时；`go test -cover`、`go test -race`、`go vet` 不适用于本 TS 插件。

## 主动声明

这些限制不会阻止本地自用和评估，但会阻止把本项目描述成“生产级、跨租户、有 SLA 的服务”。如果后续要对外提供托管/生产服务，需要先补监控、备份、限流、租户隔离、并发压测和物理设备矩阵。
