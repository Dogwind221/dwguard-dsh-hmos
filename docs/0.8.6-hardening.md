# 0.8.6 发布链路与运行时加固

0.8.6 修复 0.8.5 复核中确认的高价值工程问题。

| 问题 | 0.8.6 实现 | 回归 |
| --- | --- | --- |
| 发布链路未构建/测试/校验 tag | `publish.yml`：`npm ci → typecheck → build → git diff --exit-code → test → tag/version → npm pack 内容校验 → publish`；`pretest` 先 build；`prepublishOnly` 同样跑 typecheck/build/test/pack gate。 | `scripts/verify-publish.mjs`，工作流步骤 |
| Windows `shell:true` 注入 | `quoteShellArg` 先拒绝 `& \| < > ^ % !` 与换行/反引号，再处理空格/引号；命令路径同样检查。 | `tests/security.test.mjs` |
| 截图退出 0 但无文件 | `validateImageFile` 校验存在/非空/大小/PNG-JPEG magic；`screenshot` 失败；pipeline 校验 screenshot 与 layout 产物。 | `tests/deveco.test.mjs` |
| stdout/stderr 无上限、超时不杀树 | 输出合计 4MB 上限；超限/超时调用 `killTree`（Windows `taskkill /T /F`，POSIX 进程组）。 | 代码路径；截图/超时测试 |
| 证据 symlink/Junction 逃逸 | `resolveSharedPath` 之后 `realpath` + relative 包含检查。 | `tests/security.test.mjs` |
| PNG 解码炸弹 / 网络大响应 | 单边 8192、3200 万像素、IDAT 20MB、解压 160MB；HTTP 响应 4MB 流式上限。 | `tests/security.test.mjs` |
| 向量缓存身份只含 model | `DesignEmbeddingCache` / `ClipCache` 存储并校验 `identity`；identity = provider + endpoint + model + modelVersion；cache key 使用 identity。 | `tests/security.test.mjs` + design tests |
| 后台日志无上限 | `run/log` 每 5s 检查，超过 `maxDevecoLogBytes`（默认 10MB）快照到 `output.log.1` 并截断当前日志；`jobs`/`stop` 停止 guard。 | `tests/deveco.test.mjs` |

## 兼容性变化

- `embeddings.json` / `clip-embeddings.json` 升到 schema 2；旧缓存（无 identity）会被丢弃并重建。
- 含 shell 元字符的参数（例如带 `&` 的 verify plan）会被拒绝；这是有意的安全边界。
- 截图路径必须产生真实 PNG/JPEG；以前只看退出码的“空成功”会失败。
- 超过 4MB 的 CLI 输出/HTTP 响应会被拒绝。

## 边界

- `killTree` 在 POSIX 依赖进程组；如果子进程自行 daemonize 到新组，仍可能脱离。
- HTTP 上限只覆盖 `image.ts` / `design.ts` 的 embedding 请求；未来新增网络调用必须复用 `readResponseTextLimited`。
- `npm ci` 需要 lockfile 与 registry；离线环境需先缓存。
- 0.8.6 不替代 0.8.5 的 strict evidence / 设备 lease / 看板边界。
